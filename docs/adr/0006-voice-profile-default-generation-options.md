# VoiceProfile gains a `defaultGenerationOptions` object, absorbing the existing `language` field

`VoiceProfile` gains one new optional field, `defaultGenerationOptions: { targetLength?: number; variantCount?: number; language?: string; diacritics?: "default" | "strip" }`, mirroring the Engine's forthcoming `options` object field-for-field so a profile's defaults can be spread directly into a `generate()` call, and whatever a session actually sends (defaults or overridden) is the same shape stored on that generation's history record. `targetLength` is a plain word count, matching the convention already seen in custom-profile prompt text ("Target length: [LENGTH] words") rather than inventing a unit enum. `variantCount` is bounded `1–6` at the schema level (Zod), keeping a single-response JSON payload sane rather than scattering a ceiling across UI and Engine call sites. `diacritics` is an enum rather than a negatively-named boolean, leaving room for a future explicit "force" mode without a breaking type change.

The existing top-level `language` field (already implemented — `prompt.ts` already turns it into "Respond in {language}.", and its absence already means "infer from the input", exactly the default this options object needs) moves into `defaultGenerationOptions.language`. We considered leaving it where it is and only adding the three new fields as their own nested object, but rejected that: it isn't exposed in any app UI yet, so there are no external consumers to break, and leaving one generation-related field top-level while the other three live in a nested object would be an inconsistency with no offsetting benefit.
