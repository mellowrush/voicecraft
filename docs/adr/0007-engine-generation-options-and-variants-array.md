# Engine's `generate()` gains a request-level `options` field and returns an array of variants in batch mode

`generate()`'s `request` object gains an optional `options: GenerationOptions` field (the same shape as `VoiceProfile.defaultGenerationOptions` from ADR-0006 — `targetLength`, `variantCount`, `language`, `diacritics`), sitting alongside `profile`/`text`/`mode`/`context`. It belongs on `request`, not on the second `opts` argument, because it's about *what* to generate, not how the call executes (`opts` stays reserved for execution mechanics — `stream`, `signal`).

The batch return shape changes from `Promise<{ text: string }>` to `Promise<{ variants: string[] }>` — a breaking change to the Engine's public contract. Existing callers (the Mac app's HUD, `DiffView`, `useVoicecraftApp`) migrate to read `variants[0]` in place of `.text`; this ADR does not perform that migration, only specifies the target shape. The streaming return shape (`AsyncGenerator<{ delta: string }>`) is untouched: when `options.variantCount` is greater than 1, the Engine silently falls back to batch regardless of `opts.stream`, buffering the full provider response and returning once parsed, rather than throwing or inventing multi-variant streaming semantics that don't exist anywhere in this system. We considered erroring instead of falling back, but rejected it — streaming is a UX nicety a caller shouldn't need to know is incompatible with a setting it may only be passing through from a Voice Profile's defaults, and this repo already prefers "return what's usable" over erroring on a structural mismatch (see the partial-success policy on wayfinder map #58).

The `Provider` contract (ADR-0002) does not change: a Provider is still a thin `(prompt, opts) => Promise<{ text: string }> | AsyncIterable<{ delta: string }>` function. The Engine builds a prompt asking the model for N variants as a JSON object (per the parsing convention researched for wayfinder ticket #62 — `{"variants": [...]}`, with a delimited-text fallback) and parses the Provider's raw text response into the `variants` array itself; the Provider never sees `options` or participates in parsing.

Field name is `variants`, not `texts` or `results` — "Variant" is the term already used throughout the app's UI and this map's tickets for one generated alternative, so the Engine's return shape now matches; CONTEXT.md gets a glossary entry for it.
