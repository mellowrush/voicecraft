# Engine normalizes every Provider error into a typed `EngineError`

`generate()` catches whatever a `Provider` throws and normalizes it into a typed `EngineError` (`code: invalid_request | provider_error | rate_limited | aborted | unknown`), rather than requiring providers to throw properly-typed errors themselves or letting raw provider errors propagate. The one exception a provider author can opt into is throwing a recognized `RateLimitError` (with optional `retryAfterMs`), which core detects via `instanceof` and maps to `code: 'rate_limited'`; anything else caught becomes `provider_error`/`unknown`. We considered requiring every provider implementation to throw `EngineError`s directly, which would be simpler for core but pushes contract compliance onto every provider author and risks silent drift; normalizing centrally guarantees the one-stable-error-shape promise holds even when a provider author gets it wrong. There is no `network_error` code — core can't distinguish a network failure from any other provider failure, since the network call happens inside the caller-supplied provider, not core.
